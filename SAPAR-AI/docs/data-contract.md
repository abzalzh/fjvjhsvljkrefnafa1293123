# Контракт данных для Ерасыла

Предложенная версия 1.0. Полная схема — `dataset.schema.json`, исполняемая модель — `backend/app/schemas/contracts.py`. Структуру проверяет `scripts/validate_data.py`. Скрипт не ходит по ссылкам и не подтверждает правдивость сведений.

Четыре UTF-8 JSON-файла: `destinations.json` — массив Destination; `sources.json` — массив Source; `costs.json` — массив CostRule; `transport.json` — объект `{connections:[],routes:[]}`. При загрузке они объединяются в Dataset, версия 1.0. ID состоят из букв ASCII, цифр, `_` и `-`; уникальны внутри коллекции.

## Объекты и источники

Destination: название, описание, регион, координаты, interests, visit_minutes, transport, open_months, opens_minute, closes_minute, infrastructure, warnings, source_ids. Время задано местными минутами после полуночи. Для круглосуточного объекта укажи подтверждённые 0 и 1440. Если часы или длительность неизвестны, передай null — объект виден в каталоге, но маршрут с ним не рассчитывается.

Infrastructure не должна заполняться догадками: `unknown` отличается от `no`. Ограничения доступности, сезона и связи отражай также в warnings. При `require_accessible=true` допускается только `accessible=yes` для каждого объекта.

Source: `{id,title,url,checked_at}`. URL должен вести на источник сведений, дата — фактическая дата проверки. Каждая стоимость, связь, маршрут и объект ссылаются на источники. JSON Schema проверяет формат URL, но не содержание страницы, актуальность или качество источника.

## Стоимость

CostRule: `{id,estimate,basis,capacity,kind,source_ids}`. `estimate` — `{min_kzt,max_kzt}` или null. `kind` — `verified | estimate | unknown`; unknown требует null. Для бесплатного входа создай явную нулевую стоимость с источником, а не пустой список активностей.

- `basis=person`: ставка × число путешественников.
- `basis=group`: ставка один раз на группу.
- `basis=unit`: ставка × ceil(путешественники/capacity), например номер на двоих или автомобиль на четверых.

Стоимость питания задаётся на день, проживания — на ночь, транспорта — на **одно указанное направленное соединение**, активности — на одно посещение. Алгоритм сам умножает питание на days, проживание на days−1, транспорт на число использованных legs. Не записывай цену туда-обратно в каждое направление: это удвоит расходы. Для пакетного тарифа нужно согласовать модель разбивки до добавления данных.

Все дополнительные обязательные активности конкретного посещения перечисляются в `activity_cost_ids[destination_id]`. Неизвестная обязательная стоимость исключает маршрут, а не считается нулём. Максимальная отдельная ставка — 1 млрд KZT, только целые тенге.

## Соединения и проверенные шаблоны

TransportConnection: ID, origin/destination (ID города или объекта), transport, minutes, distance_km (может быть null), cost_id, departures, source_ids. Связи направленные; обратное плечо всегда задаётся отдельно. `departures` — список времени отправления, [] означает отсутствие отправлений. null означает свободный выезд и допустим только для car/taxi; public/tour без расписания не попадут в результат.

RouteTemplate: ID, name, origin, transport, days, food_cost_id, accommodation_cost_id, activity_cost_ids, max_travelers, available_from/until, source_ids, warnings. `days` — список `{destination_ids,connection_ids}`. Для N посещений нужны N+1 соединений.

**Первая версия поддерживает поездки с возвратом в исходный город каждый вечер.** Порядок каждого дня: город → объекты → тот же город. Проживание рассчитывается в исходном городе между днями. Многодневные линейные туры с ночёвками у разных объектов пока не поддерживаются; не пытайся записать их как дневные возвраты. Можно расширить модель совместно после первого рабочего сценария.

`available_from/until` — интервал, для которого автор проверил применимость всего шаблона: расписания, цены, режимы работы, питание, ночёвки, сезон, ограничения дней недели. Сейчас расписание одинаково для всех дат внутри интервала. Если автобус только по выходным, задай отдельные шаблоны на конкретные даты или согласуй расширение схемы. Не выдавай редкое расписание за ежедневное.

`max_travelers` ограничивает вместимость всего шаблона. Для нескольких автомобилей/номеров стоимость `unit` учитывает число единиц, но наличие этих единиц всё равно должен подтвердить автор шаблона. В warnings укажи необходимость предварительного заказа/подтверждения.

## Порядок импорта

1. Посмотри `backend/tests/fixtures/demo/` только как пример структуры: всё содержимое синтетическое.
2. Заполни четыре production-файла. Источники и цены проверь вручную.
3. Запусти `python scripts/validate_data.py data` из корня с установленными зависимостями.
4. Передай изменения Абзалу; при структурных ошибках исправь данные или согласуй изменение контракта.
5. Перезапусти backend. Загрузка атомарна: сначала валидируется весь набор, затем заменяется снимок в SQLite. Повреждённый набор не запускает сервер с частично импортированными данными.

Для начала достаточно одного реально проверенного доступного шаблона; до 15–20 объектов расширяй базу после проверки всей цепочки.
