# Самир — инструкция для твоей нейросети

Передай нейросети весь пакет SAPAR-AI и следующий запрос:

> Я Самир, отвечаю за frontend SAPAR AI по общему ТЗ. Абзал подготовил backend и предложенный контракт v1.0. Сначала прочитай README.md, docs/api-contract.md, docs/openapi.json, integration/api-types.ts и integration/api-client.ts. Реализуй мою часть в frontend/, не меняя backend и формат API. Вопросы по контракту фиксируй отдельно. Копируй клиент и типы в frontend/lib/sapar/ или импортируй их из общей папки с корректной настройкой проекта. Сервер доступен через NEXT_PUBLIC_API_BASE_URL, например http://localhost:8000 (без /api). Все расчёты выполняются backend. Генерация и пересчёт принимают полные TripPreferences; budget_kzt — общий бюджет всей группы на всю поездку. Обрабатывай success, no_results, ошибки HTTP, сетевые ошибки, отмену и устаревшие ответы. Для разработки подключи backend в явно обозначенном demo-режиме либо используй integration/examples/*.demo.json как mock adapter. Не выдавай примеры за реальные маршруты. Не рисуй точные дороги по прямым линиям. Сделай пользовательский сценарий из ТЗ, а AI подключай через готовые endpoints. Сначала добейся работающей формы → генерации → сравнения → деталей → пересчёта. Не создавай другую структуру ответов ради удобства UI.

## Что важно заранее

- `destinations` возвращает массив, не `{items:[]}`.
- В формах «Алматы» отправляется как `Almaty`.
- Время itinerary — минуты после полуночи, даты отдельно для каждого дня.
- `budget_breakdown.*` — диапазоны, не числа.
- `estimated_total_kzt` — верхняя граница диапазона, не обещанная цена.
- `recalculate` может вернуть совершенно другой набор trip ID.
- `unknown_fields` нужно показывать как отсутствие подтверждения.
- Тексты backend пока на русском; для RU/KK/EN используй коды и свои сообщения.
- `parse.status=fallback` — нормальный сценарий без Groq. Не показывай успешное применение изменений, когда changes пуст.
- Explain принимает `trip_id` и актуальные `preferences`; сервер не принимает доверенный рассчитанный маршрут от клиента.
- После AI parse покажи changes пользователю, затем отправь возвращённые полные preferences на recalculate.
- Для паспорта сохраняй весь TripOption, preferences и дату сохранения; не требуй backend для офлайн-просмотра.
- Для реального frontend URL сообщи Абзалу точный origin, чтобы он настроил CORS.

Перед объединением: строгая TypeScript-проверка, production build, проверка пустого каталога, ошибок, demo-плашки, отмены предыдущего запроса, офлайн-паспорта. Общая проверка frontend пока не выполнена, потому что frontend ещё не существует.
