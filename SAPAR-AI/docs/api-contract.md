# Предложенный API v1.0

Источником схем служит `backend/app/schemas/contracts.py`; OpenAPI экспортируется в `docs/openapi.json`. Это предложение для первоначального согласования, а не уже согласованное решение команды.

## Основные операции

- `GET /api/health`: статус процесса, `data_mode`, число объектов/шаблонов, `dataset_ready`, `ai_configured`. Готовность означает наличие структуры, а не проверку внешних источников и всех пользовательских запросов.
- `GET /api/destinations`: массив объектов. Необязательный `?interest=nature`.
- `GET /api/destinations/{id}`: один объект или 404.
- `POST /api/trips/generate`: полные `TripPreferences` → `TripResponse`.
- `POST /api/trips/recalculate`: **тот же полный запрос**, повторная генерация; не PATCH, не произвольные коэффициенты и не сохранение старого trip ID. Набор вариантов может измениться.
- `POST /api/ai/parse`: `{text, preferences}` → `{status, changes, preferences, warnings}`.
- `POST /api/ai/explain`: `{trip_id, preferences, language}` → `{status, explanation}`. Backend сам пересчитывает маршрут перед объяснением; клиент не передаёт доверенные цены.

## Входные поля

`origin` — строковый идентификатор города, по умолчанию `Almaty`. Регистр и внешние пробелы нормализуются при сравнении. «Алматы» и `Almaty` не считаются автоматически одним ID: UI показывает локализованное название, отправляет `Almaty`.

`budget_kzt` — целое неотрицательное число, общий бюджет всей группы на всю поездку. Нулевой бюджет допустим: при платных вариантах ответ будет `no_results`.

`days` — 1–14, `travelers` — 1–20, целые. `transport` — `public | car | taxi | tour`; `interests` — до 20 строковых ID. `language` — `ru | kk | en`. Коды ошибок стабильны, текущие пояснения backend на русском; UI переводит коды, AI получает запрошенный язык.

`start_date` — ISO-дата или null. Если не задана, используется текущая дата в `Asia/Almaty` с явным предупреждением в маршруте. `max_day_minutes` — 60–840, по умолчанию 600; `require_accessible` — boolean, по умолчанию false. Неизвестные поля запрещены.

## Результат

`status=success` содержит 1–3 разных варианта, если они доступны. `status=no_results` — HTTP 200, `trips=[]` и `reasons[]` с `code`, `message`, `suggested_fields`. Доступность трёх вариантов не обещается.

Стоимость каждой категории — `{min_kzt,max_kzt}`. `estimated_total_kzt` равен **верхней границе**, а не средней цене. `remaining_budget_kzt = budget_kzt - max_kzt`. `within_budget` проверяется по верхней границе. `feasibility=estimated` — результат расчёта, не гарантия реальной доступности/безопасности.

Маршрут содержит объекты с координатами, использованные транспортные соединения, дневное расписание, источники с датами проверки, предупреждения и `unknown_fields`. `itinerary.items` имеет тип `travel | visit | wait`, время в минутах после полуночи местного дня. Дни начинаются в 09:00; ожидание включено в дневной лимит. Идентификатор `reference_id` ссылается на объект/соединение. Точная геометрия автомобильного пути не предоставляется.

`category` — `economy | balanced | activities`: сначала выбирается самый дешёвый, затем лучший по score из оставшихся, затем вариант с наибольшим числом уникальных объектов из оставшихся. Это эвристические ярлыки; один маршрут не дублируется в разных карточках.

`data_mode=demo` требует видимой отметки «Тестовые данные». Примеры с суффиксом `.demo.json` нельзя использовать как настоящие туристические сведения.

## Ошибки и AI

Ошибки имеют `{error:{code,message,details}}`. Некорректный запрос — 422, отсутствующий объект/выбранный маршрут — 404, неожиданная ошибка — 500 с нейтральным сообщением. UI отдельно обрабатывает сетевые ошибки и `no_results`.

AI отсутствует по умолчанию: parse возвращает `fallback`, пустые изменения и исходные параметры. Explain возвращает программное объяснение из рассчитанных данных. Ошибки, таймауты и некорректный JSON провайдера не отключают планировщик. Валидность параметров не доказывает соответствие смыслу текста — это проверяет AI-модуль и его тесты; UI должен показать предлагаемые изменения до применения.

Для симулятора отменяй предыдущий fetch через AbortController и показывай только последний ответ. API не хранит путешествия пользователей: офлайн-паспорт хранит frontend.
