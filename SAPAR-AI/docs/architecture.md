# Архитектура backend

FastAPI routers принимают Pydantic-модели → Repository читает валидированный JSON-снимок из SQLAlchemy → чистая функция planner.generate рассчитывает варианты → Pydantic сериализует ответ. AI вызывается только отдельными endpoints, основной генератор от него не зависит.

SQLite хранит единственную активную версию датасета в JSON-колонке `dataset_snapshots`. Это сознательно простая MVP-реализация: данные импортируются из четырёх файлов при старте; запросы не изменяют каталог. ORM не создаёт отдельных таблиц для каждой вложенной модели. Сессия SQLAlchemy создаётся и закрывается на каждый доступ, глобальные изменяемые сессии не используются. Пользовательские запросы и секреты не сохраняются.

Для нескольких workers они должны читать одинаковые файлы и версию схемы. Горячее обновление каталога и миграции схемы здесь не реализованы. Для PostgreSQL потребуется соответствующий драйвер и отдельная проверка: текущая поставка проверена на SQLite.

## Алгоритм

Фильтры последовательно проверяют город, транспорт, точное число дней, вместимость, даты, доступность, интересы, обязательные цены и время. Затем строится расписание с 09:00: поездка, ожидание открытия/отправления, посещение, возврат. Весь день, включая ожидания, должен помещаться в max_day_minutes. Цены суммируются целыми тенге, интервалы складываются по границам, бюджет проверяется по верхней.

Score: 50 × доля совпавших интересов + 20 × доля используемых ставок с kind=verified + 20 × доля оставшегося бюджета + 10/(1+число неизвестных инфраструктурных полей). Это прозрачная эвристика, не оценка вероятности и не доказательство достоверности источников. Количество активностей применяется при выборе третьей альтернативы.

Основные ограничения: только заранее проверенные шаблоны, возврат в базовый город ежедневно, фиксированное начало 09:00, одинаковые ежедневные часы/расписания внутри интервала, нет live-бронирования/пробок/погоды. Бюджет питания учитывается, отдельные перерывы на еду не добавляются: длительности посещений и запас в шаблоне должны это учитывать. Не расширяйте подтверждённую доступность шаблона за пределы его источников.

## AI-граница

`services/ai_gateway.py` принадлежит backend. Ерасыл реализует отдельный `services/ai/` с асинхронным провайдером. `create_app(ai_provider=provider)` подключает его. Gateway задаёт timeout, проверяет изменения через TripPreferences, не доверяет ценам клиента и возвращает fallback. Провайдер обязан не блокировать event loop; синхронный вызов Groq внутри async-функции не подходит.

Gateway не может формально доказать фактическую корректность свободного текста AI. Ерасыл отвечает за grounding, инструкции модели и семантические тесты. При сомнениях безопаснее программный fallback. Клиент показывает proposed changes перед пересчётом.
